Glossary

Glossary of design-tool terms

The vocabulary that makes the difference between "it imported" and "it still works" — written for someone moving a real file between tools.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·7 min read
Download FigCraftOpen the studio

How to read this list

These are definitions in the sense a working designer needs, not dictionary entries: each one says what the thing is and where it bites when a file moves between Figma and FigCraft. Where a term has a specific meaning in FigCraft's own documentation, the definition follows that usage.

Two entries near the end — .figcraft and .fig — are the ones to read first if you are mid-migration, because they define what you actually own. The rest run from structure to styling to handoff to the web platform, rather than alphabetically. If you only want the task, the guides on opening a .fig file and migrating from Figma put these words to work.

The terms

Auto layout

A frame that positions its children by rules — direction, gap, padding, alignment, Hug/Fill/Fixed sizing — instead of by free coordinates. It is the first thing to check after an import, because children of an auto-layout frame are placed by the layout, not by x/y.

Component

A reusable master layer. Editing the component updates its instances; FigCraft supports components, sets, properties and detaching, and the engine treats all of it as ordinary commands.

Instance

A copy linked to a component. It inherits the master's properties and can carry overrides of its own. Overrides on swapped instances are a known import casualty, so verify them by hand.

Variant

One named state of a component — size, tone, state — selected through properties rather than by swapping files. Variants live inside a component set and are addressed by property values.

Component set

The container that groups variants of one component and defines the properties used to switch between them. A set is the unit you publish and the unit a designer picks from.

Variable

A named value — colour, number, string, boolean — that layers bind to instead of holding a literal. Change the variable and every bound field follows, which is what makes themes and density switches practical.

Mode

One value set of a variable collection: Light and Dark, or Comfortable and Compact. A layer follows the mode in force; the first mode in a collection is the default.

Alias

A variable whose value is another variable rather than a literal. Aliases build the token hierarchy — brand blue to surface to button — so a change at the top propagates without touching the middle.

Vector network

A vector shape stored as connected points and segments rather than a fixed path. It allows editing any segment without re-drawing the shape, and it is what makes boolean operations editable afterwards.

Boolean group

A group that combines shapes with union, subtract, intersect or exclude, keeping the operands editable. Unlike a flattened path, the inputs stay selectable and the result stays live.

Constraint

A rule for how a child moves or resizes when its frame resizes — pin to an edge, centre, scale. Constraints apply to free-positioned children; auto-layout children are governed by the flow instead.

Prototype flow

A named starting point plus the connections reachable from it: triggers, actions and transitions. Flows are what the presentation view plays, and what a reviewer clicks through.

Dev Mode

The developer-facing view of a design: measurements, spacing, annotations and generated code, with a ready-for-dev status per frame. In FigCraft the equivalent surface is Inspect, fed by the same engine.

Inspect

FigCraft's handoff panel. It reports layout, typography, fills, strokes and effects with their style and variable names, and generates CSS, HTML, React, Leptos, SwiftUI or Compose for a selection.

Design token

A named design decision — colour, spacing, radius, type step — stored once and referenced everywhere. Tokens are a convention; variables are the mechanism FigCraft provides for them.

MCP

The Model Context Protocol, a standard way for an AI agent to call tools. FigCraft's MCP server exposes the same 400+ commands as the UI, so an agent can create, edit, inspect and export without a private API.

WASM

WebAssembly: the compilation target that lets the Rust engine run in a browser tab. FigCraft's web build is the same editor compiled to WASM, not a reimplementation in JavaScript.

DPR

Device pixel ratio: how many physical pixels back one CSS pixel. A 2x export is not a DPR setting; it is a scale factor applied at export time, which is why a 2x PNG and a zoomed canvas are different things.

WCAG contrast

The contrast ratio between text and its background, with 4.5:1 as the usual AA threshold for body text and 3:1 for large text. It is measurable before export, which is the point of a contrast checker.

OKLCH

A perceptual colour space with lightness, chroma and hue. Editing in it keeps lightness steps visually even, unlike HSL, where equal lightness numbers look unequal. Useful for generating token ramps.

.figcraft

FigCraft's native document: an archive stored on disk, holding the document, its styles, variables and images. It is what you own — no account, no server, no telemetry — and the format every script and export reads.

.fig

Figma's document format. FigCraft imports it on a best-effort basis and large files are a known failure mode, so import a copy, save a .figcraft, and keep the original.

Where a definition is a matter of another product's current behaviour — Figma's, or a browser's — treat it as context rather than a specification. The FigCraft-specific entries follow the project's documentation for v0.9.0.

Words that are easy to mix up

  • Variant vs modeA variant is a state of one component, chosen per instance. A mode is a value set of a variable collection, applied across many layers at once.
  • Alias vs tokenA token is the idea; an alias is how one token points at another inside the tool. You can have tokens without aliases, but not a hierarchy without them.
  • Component vs instanceThe component is the source of truth; the instance is a reference to it. Editing an instance's override does not edit the component.
  • Constraint vs auto layoutConstraints describe how a child reacts to its frame resizing. Auto layout decides where the child sits in the first place; the two do not apply to the same child at the same time.

For the measurements these terms imply, the screen-sizes reference and the contrast checker run in the browser, and the templates show the structure in practice.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

What is the difference between a variable and a design token?

A token is the idea — a named design decision stored once. A variable is the mechanism a tool provides to implement it: a typed, named value that layers bind to, with modes and aliases for theming and hierarchy.

What is a variant in Figma and FigCraft terms?

One named state of a component inside a component set, selected through properties rather than by switching files. A component set groups the variants and defines the properties used to pick between them.

What does .figcraft contain?

The native document: an archive on disk with the layer tree, styles, variables and images. It needs no account or server, and it is the format the CLI, the control channel and the MCP server read and write.

What is MCP and why does a design tool have it?

The Model Context Protocol is a standard interface for AI agents to call tools. FigCraft exposes its existing 400+ command layer through it, so an agent uses the same commands as the menus instead of a separate, reduced API.

Why do designers care about OKLCH?

Because it is perceptually even: equal lightness steps look equal, which makes generated colour ramps and dark-mode palettes predictable. HSL does not behave that way, which is why hand-tuned ramps drift.
