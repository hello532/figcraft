What is actually in a design-tool SVG

Export the same icon from three tools and you get three different files. Most of the difference is not artwork.

PartTypical costSafe to remove?
XML declaration + DOCTYPE~60–120 bytesYes for inline SVG and for <img> use; harmless either way.
CommentsVariable, can be hugeYes, unless you keep licence comments. Check the licence first.
<metadata>, editor namespaces200 bytes–5 kBYes. No renderer reads it.
<title> / <desc>SmallOnly if nothing depends on them — they are the accessible name for an inline SVG.
Float noise (12.000000)2–6 bytes per numberYes, to the precision you actually render at.
id attributesSmallNo. Gradients, masks, clip paths and <use> reference them; removing an id can silently break the file.

This tool removes the first five and never removes id. Numbers are only rewritten inside tags, so <text>1.2345</text> stays byte-identical — rounding visible text would be a correctness bug, not an optimisation.

Where a real optimiser still wins

  • Path rewritingDedicated optimisers convert primitives to paths, merge shapes and reduce curve precision with error bounds. This tool does none of that; it only removes overhead and float noise.
  • Duplicate definitionsRepeated gradients and clip paths are not deduplicated here.
  • Responsive cleanupwidth/height versus viewBox is a design decision. The tool leaves both alone rather than guessing.
  • VerificationThe tool re-parses the output for balanced tags and a root <svg> before showing it. That catches structural breakage, not visual regressions — render the file once before shipping.

Figma, FigCraft and most editors export with more precision than a screen can show. Two decimals is a sensible default for UI icons; use three for large illustrations and zero only for pixel-aligned shapes.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Will this break gradients or masks?

It should not: ids are preserved, so url(#id) references and keep resolving. The output is re-parsed for tag balance before it is shown. Still render the file once — structural validity is not visual equivalence.

Why does removing <title> matter?

An inline SVG uses as its accessible name. Removing it can turn a meaningful icon into an unlabelled graphic for screen readers.
