Five design tools, one page, nothing uploaded

Contrast, colour ramp, SVG minifier, viewport sizes and placeholder text — the five checks that sit between a design being drawn and a design being handed off. Each one runs locally in this page and keeps its state in the URL.

Pick a tool

Everything below runs in this page: no account, no upload, no network call after the files load. Switch tabs freely — a panel is hidden, not rebuilt, so a half-typed hex or a pasted SVG is still there when you come back.

Type or pick two colours and get the WCAG 2.2 ratio, every level threshold as a pass or fail pill, and — when the pair fails — the nearest colour that passes with hue and saturation untouched. Text size and bold are separate settings because AA wants 4.5:1 for body copy and 3:1 for large text, and the tool reports the 3:1 non-text threshold alongside them. It measures two flat colours and nothing else: no gradients, no text over photographs, no colour-blindness simulation, and no APCA.

Contrast checker

WCAG 2.2 · runs locally · nothing uploaded

Click a suggested colour to copy its hex. The URL carries the pair and the text size, so a shared link reproduces the exact check.

One base colour becomes an eleven-step 50–950 ramp in OKLCH, with the hue held constant and chroma tapered at both ends so the extremes do not turn to mud — the reason a ramp built in HSL produces uneven steps and a grey middle. Name the token, then export as CSS custom properties, a Tailwind theme, SCSS or JSON tokens. It does not choose semantic colours, does not build a dark theme, and does not promise that any pair of steps passes contrast.

Palette generator

OKLCH · 11 steps · runs locally

Click a swatch to copy its hex. The URL keeps the base colour and token name; the export format is a local choice.

Paste a design-tool export and the minifier removes the XML declaration, comments, metadata, editor namespaces and float noise, then reports the bytes before and after rather than a promised percentage. Numbers inside text elements are left byte-identical — rounding visible copy would be a correctness bug, not an optimisation — and id attributes are never removed, because gradients, masks, clip paths and use references point at them. It does not rewrite paths, merge shapes or deduplicate definitions, so a dedicated optimiser still wins on artwork.

SVG minifier

local only · output is re-parsed before it is offered

Two decimals is a sensible default for UI icons; use three for large illustrations and zero only for pixel-aligned shapes.

Logical viewport sizes for phones, tablets, laptops and desktops in CSS pixels, each with a copyable size, a copyable media query and a link that opens this site's canvas at that exact width and height — the studio accepts w and h in the query string. Filter by name or width, or narrow to one device class. It is a reference, not a spec sheet: browser chrome changes the usable height, and the breakpoint list below is a starting set rather than a strategy.

    Why these five

    They are the checks that come up between a design being drawn and a design being handed off, and they are small enough to run in one page instead of five. Each is also a page a design tool vendor tends to publish, so a decent design tool site now ships working utilities rather than screenshots of utilities.

    Check

    Contrast before review

    Text and background pairs fail review, not design. A ratio takes seconds, and the fix suggestion moves lightness while keeping the hue, so a failing blue becomes a darker blue rather than a muddy black.

    Build

    Ramps before tokens

    A ramp with a held hue gives eleven names you can paste into variables instead of inventing a shade per component. Name the steps, not the jobs: brand-600 survives a redesign and brand-button does not.

    Ship

    Weight before deploy

    Design-tool SVG exports carry an XML declaration, editor namespaces, metadata and four decimal places. Removing the overhead is free bytes, as long as ids stay where the references expect them and no number inside a text element is rounded.

Where a result maps onto FigCraft, a ramp becomes local styles and variables, and a canvas size opens the browser studio at /#demo with w and h set.

    What none of them do

    One honest line per tool, because a utility that hides its edges is worse than no utility.

    • Contrast — no simulation, no APCAIt compares two flat colours. Two colours can pass 4.5:1 and still be indistinguishable with deuteranopia; gradients, text over images and the WCAG 3 APCA model are out of scope.
    • Palette — no semantic or dark-mode coloursSuccess, warning and danger need their own hues, and a 950 step is not automatically the dark-mode version of 50. The output is sRGB hex, so P3 and print need another pipeline.
    • SVG — no path rewritingPrimitives are not converted to paths, shapes are not merged, duplicate gradients are not deduplicated and curve precision is not reduced with an error bound.
    • Sizes — not a spec sheetVendors do not publish a guaranteed CSS viewport per model, fold and zoom are not modelled, and one frame per device is not a responsive strategy.
    • Text — English lorem onlyLine counts assume a 60-character measure and a Latin word list. For RTL, CJK or accented-language testing, use real strings from that language.

    Where your state lives

    Nothing is uploaded. The contrast checker writes fg, bg and size into the URL; the palette generator writes base and name; the other three keep their input in the page only. Switching tabs does not lose what you typed, because a panel is hidden rather than rebuilt — a pasted SVG and a half-typed hex are both still there when you come back. Reloading restores contrast and palette state from the URL and starts the rest fresh.

    Questions this page answers

    Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

    Do these tools send my colours, SVG files or text anywhere?

    No. All five are static JavaScript served from this domain, with no API call after the page loads and nothing written to a server. The minifier parses and rewrites in the page; the Download button writes a local file through a blob URL.

    Why are five tools on one page instead of five pages?

    Because they are five small utilities used in the same sitting, and five separate pages meant five sets of near-identical prose around a small form. One page keeps the tools as the main event. Every old address still works: the retired URLs redirect to the matching tab.

    Can I link directly to one tool?

    Yes. The tab is in the hash — /tools/#contrast, /tools/#palette, /tools/#svg, /tools/#sizes, /tools/#text — and arrow keys move between tabs once one has focus. The contrast checker and the palette generator additionally carry their values in the query string, so a link can reproduce an exact pair or ramp.

    Are these the same tools Figma ships?

    No. They are independent implementations of the same jobs. Figma publishes a colour contrast checker, a colour palette generator and a lorem ipsum generator; these are separate versions with the same inputs and no account requirement.

    Can I use the output commercially?

    Colour values, SVG markup and placeholder text are not copyrightable in the way code is, and the tools impose no licence on their output. Your own text and artwork remain yours.

    Do the tools work offline?

    Once the page and its scripts have loaded, yes — nothing further is fetched. A hard reload without a network connection will not work, because the page itself is served from this domain.
