Breakpoints to design against

A breakpoint is where your layout changes, not where a device is. Pick the smallest set that keeps the layout sane, then test at the edges.

    Logical pixels, physical pixels and the 100vh problem

    A phone with a 1179×2556 panel reports a 393×852 viewport because the browser maps CSS pixels to several device pixels. That is the DPR column above: at DPR 3, one CSS pixel covers a 3×3 block. Design at logical pixels, export raster assets at 2× or 3×.

    Viewport height is the number that bites. Mobile browser chrome collapses as you scroll, so 100vh is larger than what the user sees. The viewport units svh (small), lvh (large) and dvh (dynamic) exist for exactly this; a full-height layout should usually use 100svh as the floor and 100dvh where resizing is acceptable.

    Safe areas

    Notches and home indicators are handled with env(safe-area-inset-*) plus viewport-fit=cover. A design that pins content to the bottom edge needs about 34px of clearance on current iPhones; keep that in the spec, not in a comment.

    Accuracy and limits

    • Not an official spec sheetThese are the logical viewports commonly reported for each device class. Vendors do not guarantee a CSS viewport per model, and browser chrome changes the usable height.
    • Not a breakpoint strategyDesigning one frame per device leads to five layouts nobody maintains. Design the content, then find where it breaks.
    • No fold or zoom modellingUsers zoom, use large text settings, and rotate. Test at 200% zoom and at 320px width before declaring a layout responsive.

    Questions this page answers

    Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

    Why does my iPhone show a different height than this table?

    Because browser chrome is part of the viewport story. Safari reports a shorter visible height with its toolbars showing, which is why dvh and svh exist. The numbers here are the full-screen logical viewport, the size you design an artboard at.

    Should I design at 375, 390 or 393?

    Pick one phone width for your base artboard and let layout adapt below and above it. 390 is the most common modern reference; 375 still covers older and smaller phones. What matters is that the layout survives 320–430 without clipping.

    What does “Open in studio” do?

    It loads this site’s browser canvas demo with the width and height already set, so you can sketch a frame at that size. It is an independent demo, not the real FigCraft editor, and nothing is saved to an account.

    Do I need a separate tablet breakpoint?

    Only if the layout needs one. Many responsive designs jump from a single mobile column to a two-column desktop layout at 768–1024px. Adding a tablet breakpoint that changes nothing is pure maintenance cost.
