FigCraft guide / Install

How to install and run FigCraft

Prebuilt installers for every platform, or build from source with Rust. Plus how the browser build differs — it runs the same editor in WebAssembly.

What are the system requirements for FigCraft?

FigCraft ships as a native desktop binary, so the requirements are modest — there is no server, no account and no GPU-heavy cloud renderer. In practice:

  • OS: macOS (Apple Silicon and Intel, universal build), Windows 10/11 (x64 and ARM64), Linux (x86_64, aarch64 and riscv64), FreeBSD x86_64, or any modern browser via the WebAssembly build.
  • Disk: the release archives are in the tens of megabytes; the browser build downloads the editor once and then serves it from cache.
  • Rust toolchain: only needed if you build from source. Prebuilt installers do not need it.
  • Fonts: the desktop build expects the separate craft-fonts repository next to the checkout. Missing fonts fall back silently — see known issues.

FigCraft is early alpha. Keep a copy of any file you open, and check the release notes before a new build.

Which download should I pick?

Every release attaches a matrix of builds. Match your OS first, then your package format, then the architecture — the release assets are named figcraft-<version>-<os>-<arch>.<format>, so the filename tells you everything.

How do I install FigCraft on Linux?

The shortest path on Linux is the AppImage: download the file, make it executable, run it. chmod +x figcraft-0.12.1-linux-x86_64.AppImage && ./figcraft-0.12.1-linux-x86_64.AppImage. There is no system-wide install step and no dependency resolution.

If you prefer a package manager, use the .deb on Debian/Ubuntu, the .rpm on Fedora/RHEL, the .pkg.tar.zst on Arch, or the .flatpak if you already run Flatpak. All of them come from the same release page, built by the same CI run, so behaviour is identical.

How to run FigCraft

Prebuilt installers for macOS, Windows, Linux, FreeBSD and the web are attached to each GitHub release. To build from source you need a Rust toolchain:

git clone https://github.com/storytold/figcraft
cd figcraft

# fonts used by the UI and the Text tool
git clone https://github.com/storytold/craft-fonts ../craft-fonts

# desktop app
cargo run --release -p figcraft

# collaboration server (optional)
cargo run --release -p figcraft-server

Browser build: install trunk and run cargo xtask wasm. FigCraft is early alpha; keep a copy of anything you open and expect some rough edges.

Using FigCraft once it runs

The browser build needs no install at all — open the studio on the main page and draw. For how the editor itself behaves (frames, handles, the icon drawer, keyboard shortcuts), see how the studio works on the main guide rather than repeating it here.

Does FigCraft have an MCP server?

Yes. FigCraft ships a Model Context Protocol server so an AI agent can design with it: create and edit layers, run any menu command, inspect the result as JSON, and look at it as a PNG. It speaks newline-delimited JSON-RPC 2.0 over stdio.

There are two ways to start it, and the difference matters:

CommandBackendUse when
figcraft-cli mcpHeadless — an in-process engine session with one untitled document, no window, CPU rendererScripted or batch work; nothing appears on screen.
figcraft-cli mcp --attach <port>Attached — drives a running FigCraft app over its control channel (figcraft --control <port>)You want to watch every change happen live.

The control channel only listens on 127.0.0.1. Attached calls are never replayed automatically after a transport failure — the app may already have applied the request before the reply was lost — so inspect the document before retrying an edit. File access can be confined with --automation-read-root and --automation-write-root.

MCP support is young and has open reports (#927, #967). The reference is docs/mcp.md.

Frequently asked about installing FigCraft

Does FigCraft have an MCP server?

Yes. FigCraft ships a Model Context Protocol server so an AI agent can create and edit layers, run menu commands, inspect the document as JSON and render it as PNG, over newline-delimited JSON-RPC 2.0 on stdio. Start it headless with figcraft-cli mcp, or attach to a running app with figcraft-cli mcp --attach <port> so you can watch the edits live. The control channel listens on 127.0.0.1 only.

What are FigCraft's system requirements?

macOS (Apple Silicon and Intel, universal build), Windows 10/11 (x64 and ARM64), Linux (x86_64, aarch64 or riscv64), FreeBSD x86_64, or any modern browser via the WebAssembly build. No server, account or GPU is required, and the download is in the tens of megabytes. A Rust toolchain is needed only when building from source.

Is there a FigCraft AppImage for Linux?

Yes. Each release attaches figcraft-<version>-linux-<arch>.AppImage alongside .deb, .rpm, .flatpak, .pkg.tar.zst and .tar.gz builds. The AppImage is a single file: chmod +x it and run it, with no system-wide install step.

Does FigCraft support FreeBSD?

FreeBSD x86_64 is supported and ships as a .tar.gz in each release. FreeBSD aarch64 was dropped as of v0.9.0 because it could not be built within the 5-hour CI limit.

Do I need Rust to install FigCraft?

No. Prebuilt installers for every platform are attached to each GitHub release. A Rust toolchain and the separate craft-fonts repository are only required when building the desktop app from source.

Does the browser build need an install?

No install at all — open the studio and the editor runs in WebAssembly. The browser build cannot open or save local files yet, so it is for trying the editor rather than real work.
