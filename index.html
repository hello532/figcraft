What FigCraft actually is

FigCraft is a clean-room, open-source design tool built around a Rust engine. The same command layer drives the desktop UI, a CLI, a JSON control channel and an MCP server — which is why an agent can do anything a person can click. It is not a thin web wrapper: the document model, renderer and layout engine are native code.

Native, not Electron

A Rust engine with a persistent document model. Edits touch only what changed, so a node in a 20,000-node file stays fast. The same engine compiles to WebAssembly for the browser build.

Layouts that build themselves

Auto layout in both directions, wrap and grid tracks, Hug / Fill / Fixed sizing, constraints, padding and gaps, with on-canvas drag handles and keyboard flow control.

Components that scale

Main components, instances with overrides, component sets and variants, properties, swap and detach, an Assets panel, local styles and variables with modes and aliases.

Real vector networks

Pen and Pencil, vector edit mode, boolean groups whose operands stay editable, variable-width strokes, shape builder, gradients, masks, blurs, noise and glass effects.

Prototype and hand off

Connections, triggers, transitions and flows; presentation view; Inspect with measurements and annotations; ready-for-dev status; CSS, HTML, React, Leptos, SwiftUI and Compose output.

Offline and yours

Files are plain .figcraft archives on your disk. No account and no telemetry; nothing leaves the machine unless you share. SVG, PNG, JPG, WebP and PDF export; .fig opens best effort.

Honest status: FigCraft calls itself early alpha — about 49% of the way to replacing proprietary tools for real work, by its own estimate. The editor works end to end, but expect rough edges, best-effort .fig import, and only a preview of multiplayer. Check the roadmap before trusting it with a team project.

Who FigCraft is for

The same file can serve a designer, a developer and an agent — that is the point of a command-driven engine. Pick the hat you are wearing.

Designers UI / UX

Familiar toolbar, layers, auto layout, components and variants, vector networks and prototypes. Work offline on a local .figcraft file, or open a Figma file best effort.

Developers handoff

Inspect measurements and annotations, mark frames ready for dev, and export CSS, HTML, React, Leptos, SwiftUI or Compose. The CLI, JSON control channel and MCP server use the same commands as the UI.

AI agents automation

400+ commands cover menus, tools and gestures. An agent can create nodes, bind variables, render and export — the docs cover the control protocol, MCP and CLI.

FigCraft vs Figma, without the marketing

They solve the same job — designing interfaces — with different tradeoffs. FigCraft wins on ownership, offline work and hackability; Figma wins on maturity, real-time collaboration and ecosystem.

“Better” depends on the job. For a solo designer who wants a local file and an inspectable engine, FigCraft is interesting now. For a team that needs multiplayer and a mature plugin ecosystem today, Figma is still the safer choice.

Penpot is the other major open-source design platform: web-first, self-hostable, and stronger on team collaboration today. Choose Penpot when you need a browser-based team workspace now; choose FigCraft when you want a native Rust app, local files and a command engine you can inspect. penpot.app

Known issues from the GitHub tracker

These are the problems users actually report on storytold/figcraft. They are not reasons to avoid the project; they are the edges to know before you trust it with a deadline. Issue state checked 2026-10-19; open the link before acting.

Large .fig imports

Importing big Figma files can fail or take a long time. The tracker has an open import umbrella (#321) and a report for large files (#574); opening large .fig files was improved in #315. Keep the original file and try a smaller page or a fresh export.

Missing fonts fall back silently

Text in a font you do not have can render in another font without a warning (#752, closed). Install the craft-fonts repo next to the app; font rescan/load work is tracked in #821.

macOS 27 / M1 launch crash

There is an open crash on launch on macOS 27.0.1 with an uncaught NSException in _NSTouchBarFinderObservation (#781). Try the latest release and report your build; do not assume every Mac is affected.

Blurred Windows UI after restore

Restored Windows windows can render a blurred DX12 UI; the fix is tracked in #779. Resizing or restarting the window is the usual workaround until it lands.

Small UI on 1440p monitors

The interface can feel small on high-DPI 1440p screens (#540). An interface-size preference is in progress (#818); OS scaling still helps today.

Web build file access

The browser build can open local files through File ▸ Open, import and drag-and-drop; the work is tracked in #830. If a picker does not appear, use a current release and check the issue.

Variable collection crashes (fixed)

Creating a local variable collection used to crash the app (#224, #613). Both are closed; update before reproducing an old crash.

CLI path roots

CLI commands are being confined to automation roots (#839). Keep figcraft-cli inputs and outputs inside the directory you launched it from.

Collaboration is a preview

Live sessions have no accounts, teams or cloud yet, and the public server is not end-to-end encrypted. Self-host the server or use local-network sharing for confidential work.

A closed issue is not a guarantee that every build has the fix: check the release date against the issue’s close date. The most useful bug report includes the OS, build, exact steps and a sample file that can be shared.

What's new in FigCraft 0.7.0

Released 2026-10-18. These are user-facing fixes from the v0.7.0 release — the kind of polish that matters more than a feature-count headline.

  • System theme from the first frame. The window follows the OS theme immediately instead of flashing the wrong theme (#262).
  • Slice export preview shows the page under it. You can see what a slice will capture before exporting (#265).
  • Double-clicking a page no longer closes the app. A small interaction bug with a large blast radius (#271).
  • Gradient icons show their gradient. The type icons now preview the paint instead of a flat glyph (#275).
  • Alignment is disabled when it cannot apply. No more dead buttons for a selection that cannot be aligned (#276).
  • Community batch: 22 reviewed fixes. A large batch of small correctness and UI fixes from contributors (#507).

If you are on an older build, update before reporting one of the issues above. Check the release date against the issue’s close date.

How to run FigCraft

Prebuilt installers for macOS, Windows, Linux, FreeBSD and the web are attached to each GitHub release. To build from source you need a Rust toolchain:

git clone https://github.com/storytold/figcraft
cd figcraft

# fonts used by the UI and the Text tool
git clone https://github.com/storytold/craft-fonts ../craft-fonts

# desktop app
cargo run --release -p figcraft

# collaboration server (optional)
cargo run --release -p figcraft-server

Browser build: install trunk and run cargo xtask wasm. FigCraft is early alpha; keep a copy of anything you open and expect some rough edges.

How the browser studio works

Three actions are enough to judge whether a design tool fits your hands: create, arrange, export. The studio keeps its state in localStorage, so a refresh does not lose your work.

  1. Create. Pick Frame, Rectangle or Text, then click the canvas. A frame is a screen; a rectangle is a block; text opens an inline editor. The canvas can be resized, recoloured, made transparent and re-gridded from the top bar.
  2. Arrange. Drag a layer, or drag one of its eight handles to resize. Snapping aligns to the grid, canvas edges and other layers; hold Alt to disable it and Shift to keep the aspect ratio. Pan with Space+drag; zoom around the pointer with Cmd/Ctrl+wheel.
  3. Export. Export PNG at 1×/2×/3×, SVG, or a JSON layer tree. Undo/redo covers every edit; copy/paste, duplicate, layer drag-reorder and autosave make it feel like a real editor.

FAQ

Is FigCraft really free?

Yes. The source is licensed MIT OR Apache-2.0 and the installers are free. You pay with your own time: it is early alpha and you run it yourself (or use the community server preview). This guide and studio are also free.

Do I need to install anything?

For the real FigCraft app, yes — download an installer or build it with Cargo. The canvas studio on this page needs no install and no account; it is an independent teaching demo, not the full editor.

How is it different from Figma?

Figma is a mature hosted product with real-time team collaboration. FigCraft is open source, offline-first and built in Rust; its multiplayer is a preview and its feature coverage is about 49% by the project's own estimate. See the comparison table above for the full tradeoff.

Does FigCraft open Figma .fig files?

Only best effort. The project says .fig import is not reliable yet; keep the original Figma file and expect fixes to be needed. Native files are .figcraft archives.

Can I use the exported JSON in another tool?

The studio's export is a plain layer list plus canvas settings (type, x, y, width, height, colour, radius, opacity, text, font size), intentionally simple so you can transform it with a script. It is not FigCraft's native file format.

Is multiplayer ready for a team?

Not yet. Live sessions are a preview: no accounts, teams or cloud, and the public server is not end-to-end encrypted. For confidential work, self-host the server or use local-network sharing on a network you trust.

Why does a large .fig import fail?

Large Figma files are a known import issue, tracked in #574 and the open import umbrella #321. Keep the original, try a smaller page or a fresh export, and check the issue for the current status. Large .fig opening itself was improved in #315.

Why is my text in the wrong font?

If a font is missing, FigCraft can fall back without a warning (#752, closed). Clone craft-fonts next to the repository and rebuild; font rescan/load work is tracked in #821.

Why does FigCraft crash on macOS 27 / M1?

There is an open launch crash report on macOS 27.0.1 with an uncaught NSException in _NSTouchBarFinderObservation (#781). Use the latest release, attach the crash log to the issue, and do not assume every Mac is affected.

Why is the UI small on a 1440p monitor?

This is tracked in #540; an interface-size preference is in progress (#818). Until it ships, OS display scaling is the workaround.

Can I customize the studio canvas?

Yes. Choose a size preset or type a custom width and height (100–2400 px), set any background colour, switch to a transparent canvas, toggle the grid and change its spacing, and use Fit or 50–200% zoom. Cmd/Ctrl+wheel zooms around the pointer.

Does the studio have keyboard shortcuts?

Yes: V/F/R/T for tools, Delete to remove, Cmd/Ctrl+Z to undo (Shift for redo), Cmd/Ctrl+D to duplicate, Cmd/Ctrl+C/V to copy and paste, arrows to nudge 1 px (Shift 10 px), Space+drag to pan, and ? for the full dialog.

Can I export SVG?

Yes. The footer exports PNG at 1×/2×/3×, SVG, or JSON. The SVG keeps frames, rectangles, text, radii, colours and opacity; the JSON includes the board settings and every layer.
