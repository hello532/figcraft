Dashboard template: a 1440 × 900 shell you can edit

A 1440 × 900 app shell with a fixed sidebar, a 64 px top bar and a content area that takes what is left. The table and charts are placeholders you replace with your own data.

What's in the starter

The project publishes the name of this starter, not its internal pages or frame sizes. What follows is a workable structure for this kind of file — a starting spec to build against — not a transcription of the shipped document. Check it against the build you actually open.

One page, three frames: the overview, a settings screen and a narrower laptop check. The sidebar and top bar are components, so both screens share them.

  • Sidebar240 px wide, a 56 px logo block and eleven 44 px nav rows, one in selected state, with a 32 px user block pinned to the bottom by a Fill spacer.
  • Top bar64 px tall: page title, a 360 px search field, two icon buttons, a 32 px avatar. Icons are 20 px strokes from the icon set.
  • Stat rowFour 266 px cards on 24 px gutters, each with a label, a 32 px figure and a delta line. The trend arrow is a component variant.
  • Data table1136 px wide, a 48 px header row and nine 48 px body rows across five columns; the name column is set to Fill so long labels truncate before the numbers do.
  • Chart panelA 1136 × 320 placeholder built from vector shapes: twelve vertical grid lines, a four-line legend and one area shape you can restyle.
  • Settings frameThe same shell with a 720 px form column: six labelled rows, three toggles and a save bar.

Canvas spec

The arithmetic matters here: 1440 minus a 240 px sidebar leaves 1200 px, and 32 px padding on each side leaves 1136 px of content. The height follows the same logic — 900 minus a 64 px top bar is 836 px.

Open it

  1. File ▸ New from template — pick the starter from the list; it opens in the current window as an unnamed file.
  2. Choose “Dashboard” — three frames land on one page, with the sidebar and top bar already turned into components.
  3. Save to .figcraft — plain archive on disk, no account. Decide the folder now; dashboards tend to grow into several files.
  4. Check fonts and blur — text needs ../craft-fonts beside the source, and any glass or blur panel is worth a second look on Windows, where DX12 blur is a known issue.
  5. Duplicate before resizing — keep 1440 × 900 intact and do your density experiments on the 1280 × 800 copy.

Make it yours

A dashboard is a density problem before it is a color problem. These four levers control density.

Auto layout

Fill the content area

Sidebar Fixed 240, content Fill, top bar Fixed 64. The stat row is a grid track row of four, and the table body is a vertical stack of Fill-width rows.

Variables

A density mode

Row height lives in a variable with a comfortable (48 px) and compact (36 px) mode. Switch the mode on the page instead of editing ninety rows.

Components

Stat card, row, nav item

Each is a component set: the stat card has a trend variant, the nav item has selected and default, the row has a hover state. Variants keep the table honest.

Handoff

Inspect is the deliverable

Measurements, annotations and a ready-for-dev mark travel with the frame. Export React, SwiftUI or Compose when an engineer wants a starting point.

What it does not give you

There is no data binding. The table is rectangles and text, the chart is a vector shape, and nothing recalculates when you change a number. That is fine for a design review and useless as a live dashboard — the starter gives you the shell, not the application.

Two rendering caveats: glass and blur effects are the least predictable part of an alpha renderer, and blur is a known issue on Windows DX12. Separately, the app's own interface is small on a 1440p display (#540, #818) — if the inspector looks cramped, that is the app chrome, not your file. Check known issues and compare sizes against screen sizes.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Does the dashboard starter use real data?

No. Every number is text and every chart is a vector shape. There is no data binding, no formula layer and no live feed; the starter is a layout with representative values, and the values exist to show alignment and truncation.

Why 1440 × 900 and not a full HD frame?

Because the starter is a laptop-first shell. 1440 × 900 leaves a 240 px sidebar and 1200 px of content, which is the width where a five-column table still reads. The 1280 × 800 frame is there to show what breaks first when the window shrinks.

Can I add a fifth stat card?

Yes, but change the grid track count rather than dragging the cards. Four cards at 266 px with 24 px gutters fill 1136 px exactly; a fifth needs either narrower cards or a wrapping second row, and grid tracks keep the gaps equal.

Does blur or glass work on every platform?

Not reliably. Blur and glass effects are supported by the engine, but Windows DX12 blur is a known issue, and the project is an early alpha. Test any translucent panel on the platforms your team actually uses before you commit to it in a spec.
