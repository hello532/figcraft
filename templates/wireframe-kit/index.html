Wireframe kit: three breakpoints, deliberately gray

Placeholders at three widths: 1440 × 1024, 834 × 1112 and 390 × 844. Gray on purpose, so a layout review stays about layout.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·4 min read
Download FigCraftOpen the studio

What's in the starter

The project publishes the name of this starter, not its internal pages or frame sizes. What follows is a workable structure for this kind of file — a starting spec to build against — not a transcription of the shipped document. Check it against the build you actually open.

Four pages: desktop, tablet, phone, and a block library. The screens are assembled from five components, and nothing on them is a final color or a final typeface.

  • Text lineA 8 px bar for body copy and a 12 px bar for headings, each with full, two-thirds and one-third width variants. No real text, so no font surprises during a review.
  • Image blockA 16:9 box with a single diagonal, available at full, half and third width. It reads as media without pretending to be a photo.
  • ButtonA 40 px outline block with three width options. Deliberately the same gray as everything else so it cannot win an argument it has not earned.
  • AvatarA circle at 24, 32 and 48 px for list rows and headers.
  • Icon placeholderA 24 px square with a 12 px diagonal, for anything that will later be an icon.
  • Three screensDesktop at 1440, tablet at 834 and phone at 390, each laid out as hero, three content sections and a footer, so the same argument can be reviewed at every width.

Canvas spec

Each width gets its own column count rather than a scaled copy: eight columns at desktop, six at tablet, three at phone. The arithmetic keeps the gutters identical at 24 px on desktop and tablet, 16 px on phone.

Open it

  1. File ▸ New from template — then choose “Wireframe kit”. The three screens open on one page, in reading order.
  2. Save it as your own file — .figcraft on disk, no account. Wireframes usually live next to the brief, so put the file there.
  3. Start from the desktop frame — it carries the most content; the tablet and phone frames are arranged to show what each breakpoint drops.
  4. Keep the blocks as instances — if you detach a placeholder you lose the swap behaviour, and the review turns into a cleanup.
  5. Turn on the prototype flow — the three screens are connected, so a review can be a click-through instead of a static screenshot.

Make it yours

The kit is intentionally poor in detail. Improve the structure, not the fidelity.

Auto layout

Blocks that hold spacing

Each section is a vertical stack with 96 px padding on desktop and 20 px on phone. Placeholder rows are Hug height, so a section grows without a single manual nudge.

Components

Swap the block, keep the slot

An instance-swap property turns a text line into an image block without changing the surrounding stack. That is how you add media mid-review and keep the pitch.

Variables

Five grays, two modes

A gray ramp of five values plus a spacing scale. A high-contrast mode for presenting on a projector is a variable change, not a second file.

Prototype

Click-through, not a diagram

Connections, triggers and transitions make the flow walkable in presentation view. There is no connector-line diagram tool, so keep the flow in the prototype, not on the board.

What it does not give you

This kit produces rectangles. It will not look like a product, and it is not supposed to: the moment a placeholder gets a real color, the review starts discussing the color. Bring the design system once the layout is agreed, and rebuild rather than restyle — placeholder components do not convert into real ones.

Annotations are yours to write: Inspect gives measurements and supports annotations, but nothing generates callouts for you. Label text is real text, so it depends on ../craft-fonts being cloned beside the source like every other starter. Check known issues before a review depends on the app, and confirm target widths with screen sizes.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Why is the wireframe kit gray?

Because a grayscale layout cannot be mistaken for a finished design. Text lines, image boxes and buttons all share one ramp, so a review can only argue about hierarchy, density and flow. Color arrives with the design system, after the structure is agreed.

Can I turn a wireframe into the finished design?

Not by restyling the placeholders. They are not real components with real content; the practical route is to rebuild the agreed layout with the design system, using the wireframe as the spec. Your spacing and column choices carry over, the placeholder layers do not.

What grids does it use?

Desktop: eight columns of 135 px with 24 px gutters inside 96 px margins. Tablet: six columns of 103 px with 24 px gutters inside 48 px margins. Phone: three columns of 106 px with 16 px gutters inside 20 px margins.

Does it include a flow diagram?

No. There is no connector-line diagram feature; the flow is a prototype made of connections between frames, played in presentation view. The Flow / Board frame simply puts the three screens side by side so a room can see them at once.
