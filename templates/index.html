How the starters are built

All eight lean on the same three engine features, which is why they survive editing.

Auto layout

Frames that reflow

Both directions, with wrap, grid tracks and Hug, Fill or Fixed sizing: a section is a vertical stack with padding, and a row of cards is grid tracks, so widths stay equal when a fourth arrives.

Variables

Tokens with modes

Local styles carry text and effects; variables carry color and spacing with modes and aliases, so switching the mode on a page restyles it without touching a layer.

Components

Variants, not copies

Buttons, rows and cards are component sets with variants and properties. Edit the main component and every screen in the starter follows.

Read this before you trust a spec

The project publishes the eight starter names and opens them from File ▸ New from template, but it does not publish their internal pages or frame sizes. The tables above are therefore a workable starting structure for each kind of file, not a transcription of the shipped document. Check them against the build you actually open.

v0.10.0 is an early alpha, about 49% parity by the project's own estimate. Text needs the craft-fonts repository cloned beside the source or it silently falls back to a system face (#821 tracks rescanning; #752 is closed). macOS 27 on M1 has a launch crash (#781), .fig import is best effort with large files still failing (#574, #321), and FreeBSD aarch64 builds were dropped in v0.9.0.

Files are plain .figcraft archives on disk, with no account and no telemetry — which also means no cloud copy to restore. Multiplayer is a preview with no accounts, teams or cloud, so sharing a starter means sharing the file. Output is where it goes next: Inspect gives measurements and annotations, a frame can be marked ready for dev, and export writes CSS, HTML, React, Leptos, SwiftUI or Compose, or SVG, PNG, JPG, WebP and PDF. The studio here takes ?w= and ?h= and has a 100 px minimum canvas.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Where are the eight starters in FigCraft?

Under File ▸ New from template. The list is mobile app, landing page, dashboard, design system, wireframe kit, social post sizes, presentation slides and icon set. There is no marketplace and no download step: the starters ship with the app, so they open offline.

Are the frame sizes on this page what the app actually ships?

No. The project publishes the eight names, not their internal pages or frame sizes, so the tables here are a workable starting structure. Treat each size as a sensible place to begin and measure the file you open before you build a spec on it.

Which starter should I open first?

Open the one whose artifact you have to hand over. For a layout argument use the wireframe kit, for a buildable screen the dashboard or mobile app, for tokens the design system, and for a deliverable outside the app the slides or social post sizes.

Do the templates cost anything, and can I use them for client work?

The starters ship with the application, and FigCraft is open source under MIT OR Apache-2.0 with no account. That licence governs redistribution — read it rather than this page — and a starter is a structure to replace with the client brand, not a finished system.

Why does text in a starter look wrong?

Almost always the font path. FigCraft needs the craft-fonts repository cloned beside the source; without it, text silently falls back to a system face and every size you tuned shifts. #752 is closed and #821 tracks rescanning once the fonts are in place.
