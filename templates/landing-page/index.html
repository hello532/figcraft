Landing page template: a 1440 px page, cut into sections

One desktop frame at 1440 px, cut into seven sections on a 12-column grid. Duplicate a section, keep the rhythm, hand the page over.

What's in the starter

The project publishes the name of this starter, not its internal pages or frame sizes. What follows is a workable structure for this kind of file — a starting spec to build against — not a transcription of the shipped document. Check it against the build you actually open.

The desktop page is a single vertical stack. Each section is its own frame with fixed padding, so you can duplicate, delete or reorder one without touching the others.

  • Navigation and heroAn 80 px nav row with four links and one button, then a hero with a 64/68 headline, a 20/30 sub-line capped at 640 px, two 48 px buttons and a 960 × 600 product shot.
  • Logo stripFive placeholder wordmarks on one row, each 120 px wide, set in one text style so they read as a group.
  • FeaturesThree 400 px cards on a grid track row, each with a 48 px icon slot, a 24 px heading and a three-line body.
  • ProofAn 800 px quote column at 32/44 next to three stacked metrics, so the numbers do not compete with the sentence.
  • Pricing, FAQ and footerThree 400 px tiers with the middle one marked, five 72 px disclosure rows, and four 288 px footer columns.
  • Mobile pageA second frame at 390 px wide with the same sections stacked in one column.

Canvas spec

Desktop uses a 12-column grid of 82 px columns with 24 px gutters inside 96 px margins — 1248 px of content. Mobile uses four 74 px columns with 18 px gutters inside 20 px margins — 350 px of content.

Open it

  1. File ▸ New from template — the starter list opens in place; no file picker, no download.
  2. Choose “Landing page” — the desktop page and the mobile page arrive as two frames on one page.
  3. Save as .figcraft — the file is a plain archive on disk. There is no account and no telemetry, which also means no autosave to the cloud.
  4. Confirm the fonts — headline sizes are tuned for the bundled faces; if ../craft-fonts is not beside the source, text falls back and lines wrap differently.
  5. Keep the grid visible — duplicate the desktop frame before you change column widths, so the original stays as the reference for section padding.

Make it yours

The page is a container for your argument. These are the four levers that change it fastest.

Auto layout

Sections that hold their rhythm

Every section is a vertical stack with 120 px top and bottom padding. The features row uses grid tracks, so a fourth card does not shrink the first three.

Variables

Type and space as tokens

An 8-based spacing scale (8, 16, 24, 32, 48, 64, 96, 120) and a text scale from 12 to 64 keep the page consistent when you add a section. A color mode holds the dark hero variant.

Components

Pricing card with a switch

The tier card is a component with a boolean property for the accent border, so the middle plan is one property change rather than a copy. Nav links and buttons are sets too.

Color

Decide the palette before the copy

Build the ramp in the palette generator, then test headline-on-hero pairs in the contrast checker.

What it does not give you

There is no responsive engine behind this page. You get two frames — 1440 and 390 — and you maintain both. Export writes CSS, HTML, React, Leptos, SwiftUI or Compose for what you selected, but it is a static snapshot of that frame at that width, with no breakpoints, no form handling and no content model.

Copy is deliberately placeholder text; generate replacement body copy with the lorem ipsum tool rather than inventing a product story inside the layout. .fig import remains best effort with large files still failing (#574, #321), and the project is an early alpha at about 49% parity by its own estimate — check known issues before you promise a date.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Is the landing page starter responsive?

It ships two frames: 1440 wide and 390 wide. There is no breakpoint engine, so the middle widths are your call — resize a copy of the desktop frame and let the auto layout stacks reflow, or design a third frame at 834.

Can I export it as a working website?

Partly. Export produces CSS, HTML, React, Leptos, SwiftUI or Compose for a frame or selection, which is a static snapshot at one width. There is no routing, no form handling and no content model; you still need your own build to ship the page.

What grid does the page use?

Desktop: 12 columns of 82 px with 24 px gutters inside 96 px margins, giving 1248 px of content in a 1440 px frame. Mobile: four 74 px columns with 18 px gutters inside 20 px margins, giving 350 px of content.

Where does the copy come from?

The starter ships placeholder text so the type scale is visible. Replace it before any review, and use the lorem ipsum tool if you need realistic line lengths while you are still deciding what the page says.
