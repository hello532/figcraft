Mobile app template: six screens at 390 × 844

A phone starter drawn at 390 × 844 with the screens most projects rewrite first. Auto layout does the resizing, so changing a headline does not break the fit.

What's in the starter

The project publishes the name of this starter, not its internal pages or frame sizes. What follows is a workable structure for this kind of file — a starting spec to build against — not a transcription of the shipped document. Check it against the build you actually open.

The document opens on a page called Mobile / iOS: six phone frames, a component sheet, and one Android frame for a density check. Lists are auto layout stacks, so rows are instances rather than copies.

  • Splash and onboardingOne splash frame and three onboarding frames, each with a 24 px dot row, a headline block and a single primary button above the home indicator.
  • Sign inEmail field, password field, one 48 px primary button, an SSO row, and a 34 px inset reserved for the home indicator.
  • Home feedA 56 px app bar set to Hug height, a vertical list of feed cards at 16 px gaps, and a tab bar held down by a spacer frame set to Fill height.
  • Detail and settingsOne long-scroll detail frame, and a settings frame built from 48 px rows grouped into three labelled sections.
  • Component sheetButton (3 styles × 3 states), list row, feed card and tab bar. Every screen uses instances of these four sets.

Open it

  1. File ▸ New from template — the eight starters live behind this one item, not in a marketplace.
  2. Choose “Mobile app” — the document opens unnamed, with the component sheet already built and the screens wired to it.
  3. Save immediately — FigCraft writes plain .figcraft archives to disk. There is no cloud copy to restore, so save under your own name before the first edit.
  4. Check the fonts — if text looks like a different typeface, the engine is falling back because ../craft-fonts is missing beside the source. See known issues.
  5. Duplicate the page — keep the untouched starter on one page and design on a copy, so you can compare against the original after a long session.

Make it yours

Four changes that do most of the work of making this file look like your product.

Auto layout

Stacks, not coordinates

Each screen body is a vertical stack: app bar Fixed 56, list Fill, tab bar Fixed 83. Change a row's padding and everything above and below follows.

Variables

Light and dark in one pass

The color variables carry both modes. Switch the mode on the page and the screens follow; then check the result with the contrast checker.

Components

One button, nine states

The button set covers three styles across three states. Per-instance label and icon overrides keep each screen specific while the shape stays shared.

Sizes

Other phones

If your team designs at 375 × 812, resize the frame and let Fill widths absorb the difference. Cross-check against screen sizes before you commit.

What it does not give you

This is a drawing, not a running app. Prototypes connect frames with triggers, transitions and flows and play in presentation view, but there is no device mirroring and nothing is compiled for iOS or Android. Parity with Figma is about 49% by the project's own estimate, so expect gaps beyond the frames.

Two frictions worth planning for. Without craft-fonts cloned beside the source, text silently falls back and every size you tuned shifts (#821 tracks rescanning; #752 is closed). And if you were going to import an existing Figma phone design instead, remember .fig import is best effort — large files still fail (#574, #321) — so rebuild these six screens by hand and keep the original file open for reference.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

What size is the mobile app starter drawn at?

390 × 844, the logical size of a current iPhone, with a second frame at 412 × 915 for Android. If your team works at 375 × 812, resize the frames and let Fill widths take the difference; the stacks reflow without manual repositioning.

Can I run the prototype on a phone?

No. Prototypes in FigCraft support connections, triggers, transitions, flows and a presentation view, so you can click through the six screens inside the app. There is no device mirroring and no build target for iOS or Android.

Why does the text use the wrong typeface?

The font engine looks for the ../craft-fonts repository cloned beside the source. Without it, text silently falls back to a system face. #752 is closed and #821 tracks rescanning once the fonts are present.

Can I import a Figma phone design instead of rebuilding?

You can try: .fig import is best effort. Large files are a known failure (#574, #321), and a phone design is exactly the kind of nested, component-heavy file that stresses the importer. Keep the original and treat the import as a reference, not a working file.
