The FigCraft MCP server

FigCraft ships a Model Context Protocol server, so an agent can create layers, run any command, inspect the document as JSON and look at it as a PNG. The difference between headless and attached is the first thing to get right.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·7 min read
Download FigCraftOpen the studio

Two backends, chosen at launch

The server speaks newline-delimited JSON-RPC 2.0 over stdio and lives in crates/mcp; the CLI starts it. In headless mode it runs an in-process engine session with one untitled document and no window, rendering with the CPU renderer. In attached mode it drives a running app over the app's loopback control channel, so you watch every change happen.

The command surface is the same 400+ commands the UI uses. That is the point: an agent calling run_command is not using a reduced API, it is using the menu.

Step by step

  1. Build the CLI. Use the absolute path to the binary in every client config; relative paths break when the client starts in another directory. 
    cargo build --release -p figcraft-cli
./target/release/figcraft-cli --help
  2. Start it headless for scripted or batch work. Nothing appears on screen, and the session is a single untitled document. 
    ./target/release/figcraft-cli mcp
  3. Or attach to a running app when you want to see the edits. Start the app with a control port first — the channel listens on 127.0.0.1 only. 
    figcraft --control 7979
./target/release/figcraft-cli mcp --attach 7979
    --attach also accepts host:port. From a source checkout the same app start is cargo run -p figcraft -- --control 7979.
  4. Register it with Claude Code. 
    claude mcp add figcraft -- /absolute/path/to/target/release/figcraft-cli mcp
claude mcp add figcraft-app -- /absolute/path/to/target/release/figcraft-cli mcp --attach 7979
  5. Or write the JSON config. The same shape works in a project's .mcp.json and in Claude Desktop's claude_desktop_config.json (Settings, Developer, Edit Config). 
    {
  "mcpServers": {
    "figcraft": { "command": "/path/to/figcraft-cli", "args": ["mcp"] }
  }
}
  6. Confine what it can touch. Both flags are repeatable, and the folders must already exist. 
    ./target/release/figcraft-cli mcp --automation-read-root /work/project --automation-write-root /work/project/out
    A write outside the roots is refused with a readable tool error and nothing is written. With only a read root, the agent cannot write at all. Combining either flag with --attach is a usage error: the app runs the commands, so start the app with the flags instead.
  7. Verify the result, do not trust the transcript. Every mutation is one undo step, and a failing command leaves the document as it was. Read the numbers back with inspect_document or get_node, then render screenshot and look at it. 
    {"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"run_command","arguments":{"command":"file.newFromTemplate","params":{"template":"dashboard"}}}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"export","arguments":{"format":"png","path":"dashboard.png"}}}

The tools an agent actually uses

ToolWhat it does
list_commandsEvery command with label, menu, shortcut, undoability and parameter docs
run_commandRun any single command, for example layout.add or inspect.code
batchSeveral commands as one undo step, all-or-nothing, with {"$step": n} references
create_node / set_propertiesCreate layers, then set geometry, fills, layout, text and constraints
inspect_document / get_nodeThe document or one layer as JSON, including resolved bounds
export / screenshotPNG, JPG, SVG, WebP, PDF, or an experimental .fig; plus a PNG view of the page
open_file / save_fileOpen .figcraft, JSON, .fig or SVG; save as .figcraft
pointer / key / type_textThe canvas gestures and keystrokes a UI-only task would need

What can go wrong

  • The session dies after one huge requestA line is limited to 32 MiB before the newline. An oversized or unterminated frame returns JSON-RPC error -32600 and closes the session without dispatching later requests.
  • An edit failed and you are not sure whether it appliedAttached calls are never replayed after a transport failure, because the app may have applied the request before the reply was lost. Inspect before retrying.
  • Your roots are rejected at startup even attachedThe flags and --attach cannot be combined. Start the app with the roots: figcraft --control 7979 --automation-read-root ... --automation-write-root ....
  • The agent reports success and the canvas disagreesKnown rough edges in the current MCP surface: open reports include #927 and #967. Verify every run with inspect_document.
  • Text sizes on the server differ from the appThe headless server indexes system fonts on first text layout. For CI-stable renders use --no-system-fonts or FIGCRAFT_NO_SYSTEM_FONTS=1.

Unverified: which third-party MCP clients work end-to-end. The configuration shapes and tool list come from the project's documentation; this page did not run a client against a v0.9.0 server.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Does FigCraft have an MCP server?

Yes. It ships as part of the project and is started by the CLI: figcraft-cli mcp for a headless session, figcraft-cli mcp --attach PORT to drive a running app. It speaks newline-delimited JSON-RPC 2.0 over stdio.

What is the difference between headless and attached mode?

Headless is an in-process engine session with one untitled document, no window and a CPU renderer. Attached drives the running app over its loopback control channel, so the user sees every change live — and attached calls are never replayed after a transport failure.

How do I stop an agent from touching the rest of my disk?

Start it with --automation-read-root and --automation-write-root. Reads must fall inside a read or write root, writes only inside a write root, and a refused path returns a tool error without writing. The folders must exist at startup.

Can an agent open my Figma files?

It can call open_file on a .fig, which is the same best-effort import the UI uses, and on .svg, JSON and .figcraft. Complex .fig files may import partially; see the .fig guide.

How do I check what the agent did?

Read it back with inspect_document or get_node, and render a screenshot. Every mutation is one undo step, a failing command leaves the document unchanged, and programmatic calls never open dialogs.
