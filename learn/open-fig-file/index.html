Opening a .fig file in FigCraft

Import is best effort, not a migration guarantee. This is the order of operations that keeps your original file untouched and tells you what survived before you start editing.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·7 min read
Download FigCraftOpen the studio

What "best effort" actually means

FigCraft reads .fig files and turns them into its own document model, then writes .figcraft. The import is explicitly best effort: where a Figma feature has no equivalent in FigCraft's model, the importer drops it. Large files are the known weak point — a big .fig can fail outright or take a very long time (#574, umbrella #321). Opening very large files was improved in #315, which is a real improvement and not a fix for every file.

So treat the import as a read-only survey. Keep the .fig. Save a fresh .figcraft. Rebuild the parts that matter, and do not plan to round-trip back to Figma from FigCraft.

Step by step

  1. Freeze the original. Copy it and take a checksum, so you can prove later that the source was never rewritten. 
    cp brand-source.fig brand-source.fig.keep
shasum -a 256 brand-source.fig.keep   # sha256sum on Linux
  2. Get the CLI before the UI. A prebuilt macOS CLI is attached to the release as figcraft-cli-0.9.0-macos-universal.zip; the Linux AppImage bundles it; otherwise build it. 
    cargo build --release -p figcraft-cli
./target/release/figcraft-cli --help
  3. Survey the file without opening a window. info prints pages, node counts, top-level frames, style and variable counts, and pushes anything it could not import to stderr as note: lines. 
    ./target/release/figcraft-cli info brand-source.fig
./target/release/figcraft-cli info brand-source.fig --json > import-report.json
    It also lists missing fonts as missing font lines, which is the fastest way to learn that half your text will render in a fallback.
  4. Open a copy, not the source. Launch the app and open brand-source.fig.keep — or keep the copy separate and open the copy. The app opens .fig through its normal open path (the file.open command, listed by figcraft-cli commands --filter open).
  5. Save as .figcraft immediately. Do not keep editing the import in memory: the native format is what autosave, recovery and every later script will use. 
    ./target/release/figcraft-cli convert brand-source.fig brand.figcraft
  6. If it stalls, slice by frame. Export the worst frames from Figma as SVG and import each one as its own document. SVG arrives as an editable frame — groups, shapes, text, gradients, masks and effects — rather than as a flat picture. 
    ./target/release/figcraft-cli convert home.svg home.figcraft
./target/release/figcraft-cli convert settings.svg settings.figcraft
  7. Diff the report against what you expected. Compare the --json node counts with the layer count in Figma. A large gap is your rebuild list, and it is much cheaper to find it now than after a day of editing.

What does not survive, as far as the tracker states

FeatureWhat happens on importIssue
Grid auto layoutComes in without tracks or cell anchors, so the layout collapses on the first edit#465
Instance-swap overridesDropped silently; the instance falls back to the main component's default#464
Import warningsThe import does not report everything it discarded, so the report is a floor, not a full list#467
Large filesCan fail or take a very long time; improvement landed in v0.9.0's cycle#574, #315
FontsText in a font that is not installed renders in a fallback, and the fallback used to be silent#752, #821

What is not in that table is the honest answer to the common question: there is no published, exhaustive list of what the importer preserves. Test with your own file, and read info output rather than a feature matrix.

What can go wrong

  • The app opens nothing for a minute, then gives upLarge-file import (#574). Check the file with info first, then split it.
  • Every text layer is in the wrong typefaceThe document names fonts this machine does not have (#752). Install them, or load them with text.loadFont over MCP; #821 added rescan and refit.
  • The import "worked" but the component grid fell apartGrid auto layout arrived without tracks (#465). Rebuild the track list; do not re-drag every cell.
  • An instance lost its swapped contentOverrides are dropped (#464). Re-apply the swap; check the overrides list, not just the canvas.

Unverified: how much of any particular file survives. The importer's coverage is file-dependent and #467 says the report can omit losses. This page did not benchmark import times, and the split-by-SVG route changes what you get — SVG import is a different importer with its own limits.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Can FigCraft open a Figma .fig file?

Yes, on a best-effort basis: .fig import is implemented and improves between releases, but features without an equivalent in FigCraft's model are dropped. Large files are a known failure mode (#574). Check the file with figcraft-cli info before opening it in the UI.

Is .fig import lossless?

No. Grid auto layout loses tracks and cell anchors (#465), instance-swap overrides fall back to the main component (#464), and the import does not report everything it discards (#467). Keep the original .fig and treat the import as a starting point.

Do I need Figma installed to open a .fig file?

No. FigCraft reads the file itself. You need Figma only if you want to export frames as SVG to work around an import that will not finish.

Should I keep the original .fig after converting?

Yes. Keep it, and keep a checksum. Export from FigCraft writes .fig experimentally, but the reliable round trip is Figma to .fig to .figcraft, one way.

Why does my text look wrong after import?

The file names fonts that are not installed on this machine, so text is laid out in a fallback. Install the families, or load them into the running session; missing fonts are listed by figcraft-cli info.
