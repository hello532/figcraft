Installing FigCraft on Linux

There is no installer wizard and no system-wide step for the AppImage: download, chmod +x, run. The package formats exist for people who prefer their distro to own the binary.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·6 min read
Download FigCraftOpen the studio

Which file do I want?

v0.9.0 attaches 29 build artifacts plus SHA256SUMS.txt. Linux builds follow the name figcraft-0.9.0-linux-ARCH.FORMAT, so the filename tells you the architecture and the package type before you download it. Match the architecture first: an aarch64 build will not start on an x86_64 machine, and that is the most common first-run failure.

Linux formats per architecture

ArchitectureFormats in v0.9.0Notes
x86_64.AppImage, .deb, .rpm, .flatpak, .pkg.tar.zst, .tar.gzEverything. The AppImage also carries a .zsync file for delta updates
aarch64Same set as x86_64For ARM servers and ARM laptops running a full desktop
riscv64.deb, .rpm, .tar.gzNo AppImage and no flatpak in this release; use the tarball or a distro package
FreeBSD.tar.gzx86_64 only — aarch64 was dropped in v0.9.0 because it could not build inside the 5-hour CI limit

Step by step

  1. Download from the release page, then verify against the checksum file that ships beside the builds. 
    sha256sum -c SHA256SUMS.txt --ignore-missing
  2. AppImage: make it executable and run it. There is no install step and no dependency resolution; the file is the application. 
    chmod +x figcraft-0.9.0-linux-x86_64.AppImage
./figcraft-0.9.0-linux-x86_64.AppImage
    The AppImage bundles the CLI too, so automation works without a second download: 
    ./figcraft-0.9.0-linux-x86_64.AppImage cli info app.figcraft
  3. Debian or Ubuntu: install the deb. apt resolves the dependencies of a local file when you give it a path. 
    sudo apt install ./figcraft-0.9.0-linux-x86_64.deb
  4. Fedora or RHEL: install the rpm. 
    sudo dnf install ./figcraft-0.9.0-linux-x86_64.rpm
  5. Arch: install the Arch package. 
    sudo pacman -U figcraft-0.9.0-linux-x86_64.pkg.tar.zst
  6. Flatpak, if you already run Flatpak. 
    flatpak install ./figcraft-0.9.0-linux-x86_64.flatpak
  7. Tarball: unpack and run the binary. This is also the FreeBSD path; check what the archive unpacks into before assuming the binary is in the current directory. 
    tar -xzf figcraft-0.9.0-linux-x86_64.tar.gz
./figcraft
  8. Prefer building it? You need a Rust toolchain, git, and craft-fonts cloned beside the project. A missing craft-fonts checkout can fall back to another font silently, so do not skip it. 
    git clone https://github.com/storytold/figcraft
cd figcraft
git clone https://github.com/storytold/craft-fonts ../craft-fonts
cargo run --release -p figcraft

The FreeBSD caveat

FreeBSD gets a single .tar.gz for x86_64 and nothing else. The aarch64 FreeBSD build was dropped in v0.9.0: it could not finish inside the CI job's 5-hour limit, which is an infrastructure constraint rather than a statement about the code. If you need FreeBSD on ARM, building from source is the route, and it is not a supported artifact of this release. Everything else on this page is Linux-only and does not apply.

What can go wrong

  • The AppImage opens and immediately exitsUsually the wrong architecture — aarch64 on x86_64 or the reverse. Check the filename against uname -m.
  • There is no AppImage for riscv64True for v0.9.0: that architecture ships deb, rpm and tarball only. Use the tarball.
  • Text renders in the wrong faceFonts come from the machine, and a missing family falls back silently (#752). Install the families the document names.
  • The whole interface is tinyA 1440p scaling problem (#540), addressed by the interface-size preference added under #818. Check that before reinstalling anything.
  • You installed a package and the CLI is missingThe AppImage bundles it as a cli subcommand; the deb, rpm, flatpak and Arch packages are not documented as doing so. Build figcraft-cli separately if you need it there.

Unverified: distro-specific runtime dependencies for the deb, rpm and flatpak, and whether pacman -U upgrades cleanly over a previous version. The filenames, the format matrix and the FreeBSD caveat are checked against the v0.9.0 release assets.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

How do I run FigCraft on Linux without installing it?

Download the AppImage for your architecture, chmod +x it, and run it. There is no system-wide install step and no dependency resolution; the single file is the application.

Which Linux packages does FigCraft ship?

For x86_64 and aarch64: AppImage, deb, rpm, flatpak, Arch package and tarball. For riscv64: deb, rpm and tarball only. All of them come from the same CI run on the GitHub release page.

Is there a FreeBSD build for ARM?

Not in v0.9.0. FreeBSD is x86_64 only; the aarch64 build was dropped because it could not build inside the 5-hour CI limit. Building from source is the only route on ARM.

Does the AppImage include the CLI?

Yes. Running the AppImage with the cli subcommand executes figcraft-cli, so ./figcraft-0.9.0-linux-x86_64.AppImage cli info app.figcraft works without a separate build.

Do I need a Rust toolchain to install FigCraft?

No, not for the prebuilt packages. You need a Rust toolchain, git and the separate craft-fonts checkout only if you build the desktop app from source.
