Migrating from Figma to FigCraft

The import gets you a document. It does not get you a working design system. This is the order that wastes the least time, and the four places the damage usually lands.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·8 min read
Download FigCraftOpen the studio

Set the expectation first

Figma is a mature hosted product with real-time team collaboration and a plugin ecosystem. FigCraft is an open-source Rust app at about 49% parity by its own estimate, offline-first, with collaboration as a preview. A migration is therefore not a switch; it is a re-platforming with a known finishing cost.

Nothing here depends on the hosted side. If your team currently lives in Figma comments, libraries and multiplayer, no part of FigCraft replaces that yet: live sessions have no accounts, teams or cloud, and the optional public server is not end-to-end encrypted.

Step by step

  1. Inventory what you actually use, and build the CLI. Count components, variants, variables and modes, and list the fonts. This list is the migration's work breakdown, and it is cheaper to make it before the import than after. 
    cargo build --release -p figcraft-cli
  2. Start with the smallest file that is still representative. A one-screen marketing page tells you more per minute than a 400-frame product file. Keep the original .fig and a checksum. 
    cp marketing.fig marketing.fig.keep
shasum -a 256 marketing.fig.keep   # sha256sum on Linux
  3. Read the import before you open it. 
    ./target/release/figcraft-cli info marketing.fig --json > import.json
    Missing fonts and repairs surface here, plus a note: line for each thing the importer could not bring in — though not for everything it drops, which is #467. If this hangs on a large file, that is #574, and the umbrella is #321.
  4. Convert and own a native file immediately. 
    ./target/release/figcraft-cli convert marketing.fig marketing.figcraft
  5. Rebuild variables and modes before you touch layout. Colours, spacing and radii as variables with Light and Dark modes are the part that keeps every later screen cheap. Audit the variable panel against your Figma inventory rather than assuming a one-to-one mapping: the import does not report everything it drops (#467).
  6. Rebuild components, then instances, then overrides. In this order: a component set without its overrides is usable, while 200 instances pointing at nothing are not. Expect the instance-swap overrides to be gone (#464).
  7. Fix fonts deliberately. Install the families on the machine, or load them into a session with text.loadFont. Text whose font is missing is laid out in a fallback, so every measurement you take before installing the font is wrong.
  8. Re-create prototype flows. Connections, triggers and transitions exist in FigCraft, but treat imported prototype data as something to verify link by link. A flow that looks connected in the layers panel is not proof that the trigger survived.
  9. Decide what stays in Figma. Comments, multiplayer review and plugin-driven workflows have no equivalent here. Splitting the work — design in FigCraft, review elsewhere — is a legitimate end state, and more honest than a half-finished all-in migration.

What survives, what usually breaks

AreaRealistic outcome
Frames, shapes, text, imagesUsually arrives; text needs the right fonts to look right
Auto layoutOften arrives; grid auto layout loses tracks and cell anchors (#465)
Components and variantsImported, but overrides on swapped instances fall back to the main default (#464)
Variables, modes, aliasesSupported in FigCraft, but expect to rebuild tables rather than trust the import
FontsThe usual casualty: missing families fall back silently (#752)
Prototype flowsVerify each link; do not assume the trigger survived
Comments, teams, pluginsNot replaced by anything in FigCraft today

The import reports less than it should: #467 covers the case where data is dropped without a warning. That is the reason this guide keeps saying "check", and the reason the report from step 3 is worth keeping.

What can go wrong

  • The import never finishesLarge-file import (#574, umbrella #321). Split the file by page or by frame before retrying.
  • Every instance looks right until you swap oneSwap overrides are dropped (#464). Re-apply overrides per instance and spot-check a sample.
  • Your grid layouts collapse on the first editGrid tracks did not import (#465). Rebuild the track definition once per frame.
  • Type is a few pixels off everywhereA missing font was substituted (#752). Install it and re-check, since auto layout will have sized around the wrong metrics.
  • A teammate cannot comment or co-editNot a bug: no accounts, teams or cloud. Self-host figcraft-server for a live session, or keep review in another tool.

Unverified: the percentage of any real file that survives, and how long a rebuild takes. Both are file-specific. This page states the failure modes the tracker documents and does not promise that everything else is safe.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Can I open my Figma files in FigCraft?

Yes, through best-effort .fig import, or by exporting frames as SVG and importing those. Complex files import partially: grid auto layout, instance-swap overrides and missing fonts are the documented casualties.

What breaks most often in a Figma migration?

Fonts first, because a missing family is substituted and everything measured around it shifts. Then component overrides on swapped instances, grid auto-layout tracks, and prototype triggers. Rebuild variables and components in that order to contain the damage.

Can FigCraft replace Figma for a team?

Not today. There are no accounts, teams or cloud, live sessions are a preview, and the optional public collaboration server is not end-to-end encrypted. Solo work on local files, or a team that splits review elsewhere, is the realistic fit.

Can I go back to Figma afterwards?

Exporting .fig exists and is labelled experimental. Do not plan a round trip: keep the original .fig, and treat FigCraft as a one-way destination for the work you move.

How do I keep my design tokens?

Rebuild them as FigCraft variables with modes and aliases, then bind the layers. The concept maps, but the table is worth rebuilding by hand rather than trusting an import that does not report everything it dropped.
