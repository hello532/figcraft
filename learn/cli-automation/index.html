Automating FigCraft with the CLI

The CLI is the same engine without a window: inspect, export, convert, render, run command scripts, and report the command table. Everything here is repeatable in CI.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·8 min read
Download FigCraftOpen the studio

One engine, no window

figcraft-cli runs the same 400+ command layer as the UI, so a script is not a second implementation with its own bugs. Bad arguments print usage and exit 2; failures exit 1; the CLI does not panic on input. On Linux the AppImage bundles it, so ./figcraft-0.9.0-linux-x86_64.AppImage cli ... is the same tool wherever figcraft-cli ... appears below.

Step by step

  1. Build it once. 
    cargo build --release -p figcraft-cli
./target/release/figcraft-cli --help
  2. Inspect before you export. info prints pages, node counts, top-level frames, styles, variables and images, and lists missing fonts. --json gives the same as a machine-readable document for a build check. 
    ./target/release/figcraft-cli info app.figcraft
./target/release/figcraft-cli info app.figcraft --json > report.json
  3. Export deterministically. A directory output gives one file per top-level frame; an extension output gives one file, chosen with --node. 
    mkdir -p exports
./target/release/figcraft-cli export app.figcraft -o exports/ --scale 2
./target/release/figcraft-cli export app.figcraft -o hero.svg --node "Hero"
./target/release/figcraft-cli export app.figcraft -o screens.pdf --page "Screens"
  4. Convert between formats. The format follows the extensions: .figcraft, .json, .fig, .svg, images, and outputs of the same families. 
    ./target/release/figcraft-cli convert app.figcraft app.svg
./target/release/figcraft-cli convert home.svg home.figcraft
  5. Run a command script. A script is a JSON array of command/params pairs, an object with a commands array, or JSON lines. It runs in a headless session and, once it is through, prints one JSON line per step. The whole script is one undo step — and all-or-nothing. 
    [
  {"command": "frame.create", "params": {"preset": "iPhone 16", "x": 0, "y": 0, "name": "Home"}},
  {"command": "node.create", "params": {"type": "text", "parent": 2, "x": 24, "y": 64, "text": "Welcome", "props": {"fontSize": 32}}},
  {"command": "layout.add", "params": {"ids": [2], "direction": "vertical"}}
]
    Save that as start.json, then run it: 
    ./target/release/figcraft-cli run start.json --out dashboard.figcraft
    In a new document the first page is id 1, so the first layer is id 2. A later step can refer to an earlier step's result with {"$step": n}.
  6. Start from a template instead of an empty page. template.list names the built-in starters; file.newFromTemplate opens one as the document the following steps act on. 
    echo '[{"command": "file.newFromTemplate", "params": {"template": "dashboard"}}]' > start.json
./target/release/figcraft-cli run start.json --out dashboard.figcraft
./target/release/figcraft-cli export dashboard.figcraft -o dashboard.png
  7. Confine the run. Both root flags are repeatable and confine every file the subcommand touches. A path outside them is refused, and the output is otherwise identical. 
    ./target/release/figcraft-cli render in/doc.figcraft -o out/ok.png --automation-read-root in --automation-write-root out
  8. Print the command table instead of guessing. Use it when a script needs a command id you have not used before. 
    ./target/release/figcraft-cli commands --filter layout
./target/release/figcraft-cli commands --json --filter export

Subcommands worth knowing

SubcommandUse it for
infoNode counts, styles, variables, missing fonts, import notes
exportFrames or a single layer to png, jpg, svg, webp, pdf, or an experimental fig
convertFormat to format, including SVG and image import
renderThe whole page as one raster, scaled to fit 16384 px
runA JSON command script, all-or-nothing
commandsEvery command with label, shortcut and parameter docs
mcpThe MCP server, headless or attached
perfSynthetic documents and a Markdown table of hot paths

What can go wrong

  • Exit 1 and no output fileA step failed and the script rolled back: nothing was written, the session's documents are as they were, and the failing line carries "rolledBack": true. Fix the step; do not retry blindly.
  • A later step cannot find the layer an earlier step madeReference the returned id with {"$step": n} rather than hard-coding an id you guessed.
  • SVG or PDF export refuses a documentVisible descendants more than 256 levels below the exported root fail by design. Use --node on an inner layer or reduce nesting.
  • Renders differ between machinesSystem fonts differ. Add --no-system-fonts or set FIGCRAFT_NO_SYSTEM_FONTS=1 to use only the built-in fonts.
  • A path outside the roots is refusedThat is the confinement working; it landed for these subcommands in #839. Widen the root, do not work around it.

Unverified: wall-clock timings for export or script runs on your documents. The 16384 px render cap, the exit codes and the rollback behaviour come from the project's CLI documentation, not from timings measured here.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Is there a FigCraft command line tool?

Yes: figcraft-cli, built with cargo build --release -p figcraft-cli or bundled in the Linux AppImage as a cli subcommand. It exposes info, export, convert, render, run, commands, mcp, plugin publish and perf.

Can the CLI run FigCraft menu commands?

Yes. run executes a JSON script of command ids and params in a headless session, printing one JSON line per step. The whole script is one undo step and is all-or-nothing, the same guarantee the MCP batch tool gives.

How do I find a command id?

Run figcraft-cli commands for the human-readable table, or figcraft-cli commands --json --filter layout for machine-readable output. The same list is available over MCP as list_commands.

Can I limit what a script may read and write?

Yes. --automation-read-root and --automation-write-root confine info, export, convert, render and run. Each is repeatable, each folder must exist, and reads are allowed inside either root while writes need a write root.

What happens if a step in my script fails?

The script stops, prints a line with "ok": false and "rolledBack": true, writes nothing including --out, restores the session documents, and exits 1.
