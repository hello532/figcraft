FigCraft keyboard shortcuts, split honestly

There are two keymaps in play on this site and only one of them is documented here. This page lists the demo studio's shortcuts, then shows how to read the real app's bindings instead of assuming they match.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·6 min read
Download FigCraftOpen the studio

Two keymaps, one of them documented

The studio at /#demo is an independent canvas built for this site. Its shortcuts are fixed, small, documented below, and shown in its own ? dialog. They are the studio's, not FigCraft's.

The real app has its own default keymap, held in one table in the engine (figcraft_engine::keymap) and grouped the way the project's shortcut reference is grouped. This guide does not reproduce that table: it changes between releases, macOS and Windows/Linux differ, and a copied list would be stale in a way you cannot see. Read it from the build you are running instead — the commands are further down.

Demo studio shortcuts (documented)

KeysAction
V / F / R / TSelect, Frame, Rectangle, Text tool
Drag / handle dragMove a layer, resize a layer
Alt + dragDisable grid and guide snapping
Shift + dragKeep the aspect ratio while resizing
Cmd/Ctrl + ZUndo; add Shift to redo
Cmd/Ctrl + DDuplicate the selected layer
Cmd/Ctrl + C / VCopy and paste a layer
Delete or BackspaceDelete the selected layer
ArrowsNudge 1 px; Shift 10 px; Alt 0.001 px
Cmd/Ctrl + arrowsResize instead of moving
Space + dragPan the canvas
Cmd/Ctrl + wheelZoom around the pointer
EscClose a dialog, drop the icon drawer, deselect
?Open the shortcut dialog

Three details worth knowing. The nudge has a sub-pixel tier — Alt moves 0.001 px, which is only visible at high zoom and is there for aligning to a grid you do not want to disturb. Holding Cmd/Ctrl with the arrows converts the same gesture into a resize. And a run of arrow presses collapses into one undo step, so undo does not walk back 40 individual nudges.

The real app's keymap (not documented in this guide)

What this guide can tell you is where the answer lives. The app's shortcuts are entries on commands: every menu action is a command, and each command may carry a shortcut. The CLI prints that table, which makes it the authoritative, version-accurate list for the build you have.

  1. Open the demo and its own dialog. Go to /#demo and press ?. What appears is the table above, with the studio's own wording.
  2. List every command with its shortcut. The commands subcommand prints label, shortcut and an undoable marker; --filter narrows it, --json makes it machine-readable. 
    ./target/release/figcraft-cli commands --filter export
./target/release/figcraft-cli commands --json > commands.json
  3. Read the platform-specific binding. list_commands over MCP reports each command's first key for the platform the server runs on, so the same dump looks different on macOS and on Linux. Run it on the machine you care about.
  4. Check an ambiguous key by its command, not by memory. Some bindings differ by platform; the project's own documentation gives Use as mask as Ctrl+Cmd+M on macOS and Ctrl+Alt+M elsewhere, and Bring to front as Alt+Cmd+] and Ctrl+Shift+]. Assume nothing you have not printed.
  5. Drive the app with a key you have verified. Over MCP, key resolves keys the way the canvas does, and run_command reaches the command behind the shortcut directly — usually the better choice for automation, because it does not depend on a keymap at all.

Unverified in this guide: the complete real-app keymap. There is no official list here to check against, and this page deliberately does not invent one. If a published shortcut reference disagrees with your build, the build is right.

What can go wrong

  • Demo keys do nothing in the appExpected. The studio's V/F/R/T bindings are the studio's. Print the app's table with figcraft-cli commands.
  • A shortcut types a character instead of runningYou are editing text. While a text layer is being edited, text shortcuts and text editing keys take precedence over canvas commands.
  • You cannot read the shortcut labels at allThe UI is small on a 1440p display (#540); the interface-size preference was added under #818. Set it before blaming the keymap.
  • The list you found online is wrongIt is probably from another version or another platform. Regenerate it from your own build.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Are the demo studio shortcuts the same as FigCraft's shortcuts?

No. The studio at /#demo is an independent canvas with its own small fixed keymap. This guide documents that keymap only, and states plainly that the real app's keymap is not documented here.

How do I find FigCraft's real keyboard shortcuts?

Print them from your build: figcraft-cli commands lists every command with its shortcut, and --json --filter narrows the result. Over MCP, list_commands reports each command's first key for the platform the server runs on.

Why do Windows and macOS shortcuts differ?

The engine keymap carries macOS keys and, where they differ, the Windows and Linux keys — for example Use as mask is Ctrl+Cmd+M on macOS and Ctrl+Alt+M elsewhere. The dump you print reflects the platform it ran on.

Can I run a command without knowing its shortcut?

Yes, and for automation you should. Every menu action is a command reachable by id through the CLI, the control channel and MCP, so run_command with the command id does not depend on a key binding at all.
