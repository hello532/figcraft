Exporting SVG from FigCraft

Two exporters share the word "SVG" here, and only one of them is FigCraft. This page covers the real exporter first, then the demo studio, and keeps them apart.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·6 min read
Download FigCraftOpen the studio

Two exporters, one name

The FigCraft app exports SVG, PNG, JPG, WebP and PDF from its own Rust engine. The same engine is reachable from the CLI with the export, convert and render subcommands, which is what you want in a build script: identical output, no window, no clicking.

The studio at /#demo on this site is a separate canvas and writes its own SVG. It is fine for a quick mockup, but it is not the app's exporter and it does not read .figcraft. If the file will be committed, minified and shipped, produce it from the app or the CLI.

Step by step

  1. Build or find the CLI. The Linux AppImage bundles it as a subcommand, so the same command works without a separate binary. 
    cargo build --release -p figcraft-cli
./target/release/figcraft-cli --help
  2. Confirm what you are about to export. Get the layer name and page name exactly right — both --node and --page accept a name or an id. 
    ./target/release/figcraft-cli info app.figcraft
  3. Export one layer to one file. An output path with an extension means one file, and --node picks what goes in it. 
    ./target/release/figcraft-cli export app.figcraft -o hero.svg --node "Hero"
  4. Export every top-level frame. An output directory gets one file per frame, named after the frame. With a directory there is no extension to infer from, so pass the format. 
    mkdir -p exports
./target/release/figcraft-cli export app.figcraft -o exports/ --format svg
    Keep frame names filesystem-safe: when layers are exported through stored export settings, a slash in a name becomes a folder.
  5. Raster versions from the same source. --scale applies to raster formats only, so a 2x context does not silently change your SVG. 
    ./target/release/figcraft-cli export app.figcraft -o exports/ --scale 2
./target/release/figcraft-cli render app.figcraft -o page.png --scale 2
  6. Convert a whole document when you want one file, not a set. convert writes the current page as SVG; for print, PDF keeps frames as separate pages. 
    ./target/release/figcraft-cli convert app.figcraft app.svg
./target/release/figcraft-cli export app.figcraft -o screens.pdf --page "Screens"
  7. Shrink the result before shipping it. The SVG minifier on this site strips whitespace and metadata in the browser, so the file never leaves your machine.

Text stays text — which is both the feature and the trap

SVG export keeps <text> elements by default: the file is editable and selectable, and its fonts are whatever the viewer has. That is why an exported SVG can look perfect in your browser and wrong on a colleague's laptop. If the text must look identical everywhere, outline it — the automation export takes svgOutlineText, and the same options can be stored per layer in export settings (export.add). The alternative is to accept that the SVG depends on a font stack you do not control.

Missing fonts are a separate failure: if the document names a family that is not installed, FigCraft lays that text out in a fallback before export, so the SVG records the wrong metrics rather than a missing font (#752). The rescan and load commands that fix a running session are covered by #821.

What can go wrong

  • The command errors instead of writing a fileSVG and PDF export refuse documents with visible descendants more than 256 levels below the exported root, rather than writing a truncated file. Select an inner layer with --node, or flatten the nesting.
  • Your old destination file is still thereOn that nesting failure the existing destination is kept. Check the exit code, not the timestamp.
  • The text is in the wrong font in the browserMissing source font (#752), or a viewer without the family. Outline the text for fixed output.
  • Nothing matches the demoThe demo's SVG comes from a different renderer. See the table above; do not diff the two files and expect parity.

Unverified: byte-level fidelity across viewers, and whether a given SVG survives every downstream tool. This page checked command syntax against the project's CLI documentation, not the visual output of a specific file.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Does FigCraft export SVG?

Yes. The app exports SVG, PNG, JPG, WebP and PDF, and the CLI writes the same formats headless with figcraft-cli export, convert and render. Inspect additionally generates CSS, HTML, React, Leptos, SwiftUI and Compose for handoff.

Is the SVG from the demo studio the same as the app's SVG?

No. The studio at /#demo is an independent canvas on this site with its own renderer and its own export set (PNG 1x/2x/3x, SVG, JSON layer tree). It cannot open .figcraft and it is not a substitute for the app's exporter.

Why is my exported text not selectable?

It was outlined. SVG export keeps <text> unless you ask for outlines, so selectable text is the default; if yours is paths, an outline option was set on the layer or in the export call.

Why does SVG export fail on a deeply nested design?

Exports with visible descendants more than 256 levels below the exported root fail on purpose instead of writing an incomplete file, and an existing destination file is left untouched. Export an inner layer with --node or reduce the nesting.

Can I export all frames at once?

Yes. Point -o at a directory with --format svg and you get one file per top-level frame, named after the frame. For PDF, frames become separate pages.
