Figma alternatives on Linux: what actually installs

Linux is where the design-tool gap is widest. FigCraft ships real packages, Penpot needs only a browser, and Graphite is the name people mention without checking.

Independent guide·Updated 2026-10-22·Covers FigCraft v0.9.0·6 min read
Download FigCraftOpen the studio

The gap, and who fills it

Figma is usable in a browser on Linux, which is enough for many people and not enough for anyone who wants a native application, a local file and a command line. FigCraft is a Rust application that ships Linux builds directly. Penpot is a web platform, so Linux support means a browser. Graphite is a third name that comes up in these conversations; we did not verify its Linux packaging or its feature coverage for this page, so it appears here as a lead to investigate rather than a recommendation.

FigCraft's Linux packages

Six formats, three architectures. Pick the one your distribution expects; there is no universal installer.

Three architectures is unusual for a design tool and matters if you work on ARM servers or RISC-V hardware. The adjacent FreeBSD port is less lucky: aarch64 was dropped in v0.9.0, so ARM coverage is a Linux feature now, not a portable one.

What to expect on Linux specifically

The first obstacle is fonts. FigCraft expects a sibling directory named ../craft-fonts next to the application; installing into /usr/bin or /opt means creating that directory deliberately and keeping it across upgrades. The issue is tracked as #821, with an earlier fix in #752 now closed, so the behaviour is known rather than mysterious.

The second is display scaling. Interface scale misbehaves at 1440p (#540, #818), which is exactly the resolution of many Linux workstations and high-density laptop panels. Windows has a separate DX12 blur problem; macOS 27 on M1 has a launch crash (#781). Linux is not the buggiest platform in that list, but it is not clean.

The third is the fallback. A WebAssembly build runs in a browser, so a machine where nothing installs can still open a document. It is the same engine with a browser's constraints, and it is the right way to test before committing to a package.

Installing, without guessing

  1. Check the architecture with your package manager, then pick the matching artefact: x86_64 for most desktops, aarch64 for ARM machines, riscv64 only if you know you are on it.
  2. Install through your distribution's channel where one exists: .deb with the system package tool, .rpm with dnf, .pkg.tar.zst with pacman, .flatpak through the Flatpak remote, or the AppImage and tarball without touching the package database.
  3. Create the font directory as a sibling of the binary, named exactly ../craft-fonts, before first launch. Font problems are the most common first-run surprise.
  4. Open a small file and export once — SVG or PNG — to confirm the whole chain before moving a real project across. Then read the known-issues list with the version you installed in mind.

The install page covers downloads per platform in more detail; this page only explains what differs on Linux.

Penpot and Graphite on Linux

Penpot needs no Linux package at all. It is web-first: a browser tab against the vendor cloud, or a self-hosted deployment if your organisation runs it, with the vendor's Private Server priced at $50,000 a year. For a Linux user the trade is straightforward — nothing to install, nothing to update locally, and no native file on disk. The free Professional tier covers 8 team members, 10GB and 7 days of history; Unlimited is $7 per editor with a $175 monthly cap.

Graphite is the other open-source name that appears in these discussions. We did not verify its Linux packages, its file format or how close it comes to Figma, so it gets no table row and no verdict. Treat it as a second tab to open rather than a recommendation from us.

Questions this page answers

Straight answers, with the limits stated. Every claim here is checkable against the sources linked above.

Does Figma run natively on Linux?

Figma is used through a browser; no native Linux build appears in the sources we checked. If you need a native binary, FigCraft ships AppImage, .deb, .rpm, .flatpak, .pkg.tar.zst and .tar.gz packages for x86_64, aarch64 and riscv64.

Which FigCraft package should I install on Ubuntu?

The .deb is the natural fit for Ubuntu and Debian derivatives, and the AppImage works everywhere without touching the package database. Both are published for x86_64, aarch64 and riscv64. Prefer the distribution package if you want upgrades handled by the system; prefer the AppImage if you want an isolated copy.

Why does FigCraft need a craft-fonts directory?

It looks for fonts in a sibling directory named ../craft-fonts next to the binary rather than relying only on system fonts. Installing into /usr/bin or /opt means creating that path yourself and preserving it across upgrades. The workflow is tracked as issue #821, still open in v0.9.0, after an earlier fix in #752.

Is Penpot a good Linux alternative to Figma?

It is a good alternative for anyone willing to work in a browser. Penpot is web-first and self-hostable, with a free Professional tier covering 8 team members, 10GB and 7 days of history, then $7 per editor capped at $175 per team per month. Nothing installs locally, which is either the advantage or the problem.

Does FigCraft support ARM Linux?

Yes: aarch64 packages exist for all six Linux formats, and riscv64 as well. Note the contrast with FreeBSD, where aarch64 support was dropped in v0.9.0, so ARM coverage should be treated as a platform-specific claim rather than a universal one. Check the release notes for your exact format before relying on it.
